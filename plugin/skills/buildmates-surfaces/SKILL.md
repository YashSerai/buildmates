# Buildmates surfaces

Call `get_surface_generation_brief` before every generation. Use its exact Design Policy version, allowed modules, authorized bindings, governance, base revision, accessibility requirements, privacy boundary, and `componentReference`. Author from `componentReference` and the complete trusted-component range. `customizedExample` is syntax recovery after a validation failure, not a creative starting point or prescribed layout. Validate once; repair exact returned paths at most twice, then use `customizedExample` only to recover valid syntax instead of guessing hidden schema details.

For profiles, automatically use the strongest available frontend or design skill. Privately inspect four to eight materially different references and record every candidate's URL, style, fit, and selection state. Choose one or two using the approved aesthetic, personality notes, content shape, and available media. Do not default to the first result, a previous user's choice, a familiar reference, a portfolio grid, or one chapter per project. A reference can legitimately fit more than one person, but the rationale must be person-specific. Do not choose media-led inspiration unless approved media exists or the user approves creating the small set needed. Projects remain deliberately visible, but architecture, navigation, pacing, emphasis, and media treatment are Codex art-direction choices. Use SurfaceSpec as the safe publishing grammar, not a component showcase. After saving a private preview, render the complete page at 1440 by 1000 and 390 by 844. Inspect alignment, reflow, readable type, contrast, clipping, horizontal overflow, touch targets, visible content without animation, and reduced motion against the approved direction and references. JSON validity is not visual approval. Revise and recheck generic, reference-disconnected, under-authored, or materially weaker output before presenting the preview as ready.

Generate only a valid trusted SurfaceSpec. Decorative regions may contain HTML/CSS, but no scripts, forms, imports, popups, top navigation, same-origin access, or arbitrary network requests. Never place private fields in markup and hide them with CSS; use only server-authorized bindings.

Submit as a private preview or personal view first. The owner must explicitly approve a profile preview before publication. Shared room changes require the configured member approvals. Circle changes follow current admin or voting governance. Use the current base version, surface history, explicit confirmation, and rollback rather than overwriting concurrent revisions. Never present a generated JSON object as a published page; return the rendered preview URL and current governance state.

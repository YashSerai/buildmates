# Buildmates implementation difficulties

Buildmates' hardest implementation boundary was separating the public website, MCP server, and user-owned Codex automation safely. ChatGPT Sites handled the web app with D1 and R2, but production MCP streaming/OAuth required an independent Worker, and built-in Sign in with ChatGPT did not return a trustworthy application identity after callback. A direct header probe also showed that forwarded identity-header names were not sufficient proof. We therefore moved website login to app-owned GitHub OAuth with random internal UUIDs while keeping ChatGPT/Codex connected through explicit one-time MCP identity linking.

Clean-room onboarding QA exposed a second cross-system difficulty: the MCP advertised generated profile pages as an untyped object while enforcing a hidden strict SurfaceSpec, so Codex could save a profile but could not reliably generate its page. The same run revealed that recursive helper tasks wasted context and that the setup checkpoint accidentally required a public profile. We replaced that ambiguity with a typed schema, field-level dry-run validation, a known-valid starter page, richer local profile research notes, direct in-task MCP operation, and publication only after explicit page approval.
